# ADR（架构决策记录）编写规则

> 适用场景：创建 `docs/adr/ADR-NNN-*.md`、为 change 的 design.md「技术选型」章节补 ADR 引用时。
> 关联索引：AGENTS.md 6.2 协同规则第 4 条。

## 一、文件与编号

- 每篇 ADR 一个文件：`docs/adr/ADR-{编号}-{英文短名}.md`。
- 编号 `ADR-NNN` **全局递增，不随 change 重置**；已有 ADR 直接引用，新增决策才新建。
- 语义短名用小写连字符（如 `ruoyi-vue-plus-6x`）。

## 二、模板

```markdown
# ADR-NNN：标题（一句话概括决策）

## 状态
已采纳 / 已废弃 / 已被 ADR-MMM 取代

## 背景
我们面临什么问题？为什么需要做这个决策？

## 选项

| 选型 | 优点 | 缺点 |
|------|------|------|
| 方案A | 优点描述 | 缺点描述 |
| 方案B | 优点描述 | 缺点描述 |

## 决策
选择 XX。（一句话，简洁）

## 理由
- 理由 1：详细说明
- 理由 2：详细说明
- 理由 3：详细说明
```

## 三、写作要求

- **选项**：表格形式，三列固定 = `选型 / 优点 / 缺点`，不少于两个候选方案。
- **决策**：一句话，直接说"选择 XX"，不含理由。
- **理由**：分条目（`-` 列表），每条写清因果；可含"代价/取舍"说明。
- **正文**：结构标题英文（`## 状态` 等）固定，内容用中文。
- 每篇 ADR 不超过一页。简洁是 ADR 的生命线。
- 不写"关联 design.md"类反向脚注（design.md 单向引用 ADR 即可）。
- 若文档模板与本规则有出入，以本规则为准。

## 四、与 design.md 的联动

- change 的 design.md「技术选型（ADR）」章节**只放引用清单**，格式 `ADR-NNN -> 语义短名`，不写决策细节。
- 决策的完整背景 / 选项 / 理由只沉淀在 ADR 文件，design.md 不重复。
