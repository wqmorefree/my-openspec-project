# ADR-004：国密分层——SM2 传输 / SM3 哈希 / SM4 敏感字段(kbcrypto)

## 状态
已采纳

## 背景
遵循国家密码体系：登录密码传输需防窃听、存储需防泄库、敏感字段需可逆加密。需确定每层算法及实现位置（应用层 vs 数据库层）。

## 选项

| 选型 | 优点 | 缺点 |
|------|------|------|
| SM2 传输（前端 sm-crypto + 后端 Hutool） | 符合国密要求；前后端库成熟 | 需替换 plus-ui 默认登录加密段，配合前端改造 |
| SM3 哈希（应用层 Hutool） | 三次迭代 + 固定盐常量，抗彩虹表；禁 MD5/SHA1 | 无法复用框架现有密码摘要实现，需写替换钩子 |
| SM4 敏感字段（应用层 Hutool） | 跨库可移植、实现直观、可单测 | 与 docs/rules 三文件（database/security/testing）强制约定冲突 |
| SM4 敏感字段（数据库层 kbcrypto） | 与 rules 完全一致（`database.md` 7.4 既有实现）；应用层无需维护密钥与加解密代码；加解密在库内完成 | 依赖金仓专用插件，换库需改造 |

## 决策
选择：SM2 传输（应用层）+ SM3 哈希（应用层）+ SM4 敏感字段（数据库层 kbcrypto），密钥经环境变量 `SM4_KEY` 注入。

## 理由
- SM4 采用数据库层 kbcrypto，与本项目 `database.md`、`security.md`、`testing.md` 三处强制约定保持一致，不自造方案。
- kbcrypto 实现已有规范支撑（`Sm4TypeHandler` 调 `sm4()` 函数，flag 0/1 加解密），实现即复用，不重写加解密轮子。
- 密钥仅需数据库层认知，应用层通过 TypeHandler 自动编排，落库即密文、读取即明文，代码侵入小。
- SM2/SM3 放应用层：登录链路改造（前端加密、后端解密还原、SM3 校验）在既有框架中更可控，也便于单元测试。
- 代价是 SM4 跨库移植性受限，但本项目固定金仓，该取舍可接受。
