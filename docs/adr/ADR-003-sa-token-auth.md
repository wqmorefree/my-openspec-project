# ADR-003：认证与权限采用 Sa-Token + JWT，权限点控删除

## 状态
已采纳

## 背景
需要登录认证与角色权限。要求：管理员/普通用户两种角色；普通用户不可删除资产记录；直调 API 也必须被拦截；不接 SSO、不做多租户。

## 选项

| 选型 | 优点 | 缺点 |
|------|------|------|
| Spring Security + JWT | 生态强、功能全面 | 配置重、门槛高，与 RuoYi-Vue-Plus 内部链路易冲突，改造成本大 |
| Sa-Token + JWT | RuoYi-Vue-Plus 内置，登录链路与用户/角色/菜单表开箱即用；配置轻量 | 权限模型跟随框架约定，不支持自定义复杂 RBAC |

## 决策
选择 Sa-Token + JWT，沿用框架内置用户/角色/权限体系（`sys_user`、角色表、菜单权限表），预置管理员、普通用户两角色。

## 理由
- 框架内置即得，无需引入额外安全框架，避免 Spring Security 与既有拦截链冲突的风险。
- 用户表、角色表、菜单权限表、登录签发流程全部开箱即用，登录改造只聚焦国密（SM2 传输、SM3 哈希）。
- 删除管控做双层拦截：前端 `v-hasPermi` 隐藏/禁用删除按钮，后端接口加 `@SaCheckPermission` 权限点，保证普通用户即使直接调 API 也被拒。
- 两角色的权限差异收敛为一个权限点（删除），模型简单清晰，管理成本低。
- 不做自定义 RBAC 的代价可接受：当前需求只有"删除仅管理员"一个边界。
