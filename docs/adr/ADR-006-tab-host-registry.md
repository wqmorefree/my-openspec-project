# ADR-006：详情页采用 Tab 宿主 + 子表组件注册表

## 状态
已采纳

## 背景
系统详情页需承载 12 大类 Tab，且按 change 逐个交付。需要一个稳定的宿主框架，使后续每个 Tab change 挂载时"框架零改动"，并保证未开放 Tab 有友好提示。

## 选项

| 选型 | 优点 | 缺点 |
|------|------|------|
| 全部 Tab 写死在详情页组件 | 直观、显式 | 11 个后续 change 每个都要改框架代码，耦合高、易冲突 |
| Tab 宿主 + 组件注册表 | 详情页只渲染已注册组件，后续 change 仅新增文件、框架零改动；未注册 Tab 显示"建设中" | 引入注册约定，需文档约定目录结构 |

## 决策
选择"Tab 宿主 + 子表组件注册表"：路由 `/system/{id}` 进入详情页，顶部渲染 12 个 Tab，仅已注册 Tab 渲染内容，未开放 Tab 显示"建设中"占位。

## 理由
- 12 个 Tab 分批交付（change 1 只开放「基础信息」），注册表让后续 change 通过"新增注册项 + 新组件文件"即可挂载，不触碰详情页骨架，最大程度降低合并冲突。
- 注册目录固定为 `src/views/system/registry/`，约定清晰，后续开发者可预测扩展方式。
- 未开放 Tab 显示"建设中"而非空白/报错，保证详情页骨架对用户始终可用。
- 路由 `/system/{id}` 固定，Tab 切换不离开当前系统上下文，URL 稳定指向该系统。
- 代价是牺牲一点显式性（Tab 与组件映射需查注册表），换取长期扩展稳定性，对本项目多 Tab 演进节奏是划算的取舍。
