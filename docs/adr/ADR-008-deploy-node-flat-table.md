# ADR-008：部署信息采用单表平铺节点模型

## 状态
已采纳

## 背景
部署信息需要登记一个系统在多套环境（生产/测试/开发）下的部署节点，每个节点含 32 个字段（主机/IP、资源规格、网络与运维配置）。需要决定这些节点在关系模型中的组织方式，既要支撑原型的登记形态，又要与 ADR-005 的"子表独立 change"约定衔接。

## 选项

| 选型 | 优点 | 缺点 |
|------|------|------|
| 单表平铺：`sys_asset_deploy` 一行一节点，sys_env 列区分环境 | 与原型平铺表格一致；表少、CRUD/导入导出简单；级联删除直接按 asset_id | 环境级总览属性无处存放；行数随节点线性增长 |
| 环境主表 + 节点明细表两层 | 环境总览与节点明细各归其位；可挂环境级属性 | 原型无环境总览字段，属过度设计；主从级联与导入解析复杂度翻倍 |
| 每系统单条总览（key-value 表单） | 登记最轻 | 无法承载多环境多节点清单，不满足原型 |

## 决策
选择单表平铺：`sys_asset_deploy` 一行一个部署节点，以 `sys_env` 字典列区分生产/测试/开发。

## 理由
- 原型本身就是单表格平铺模型，字段与交互（10 列、行级 CRUD、导入导出）直接映射，无需在实现层引入原型不存在的层级。
- 复用 ADR-005/ADR-007 范式：单层子表的 CRUD、EasyExcel 导入、CSV 导出与 asset_id 级联逻辑删除均可直接沿用 change 1 骨架，交付成本低。
- `(asset_id, sys_env, ip_address)` 部分唯一索引在单表上即可保证同环境 IP 不重复，约束表达直接。
- 代价是缺乏环境级总览载体；当前需求无环境级字段，未来若出现可再新增环境表演进，不影响本期节点数据。
