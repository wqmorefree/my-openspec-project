# ADR-001：采用 RuoYi-Vue-Plus 6.X 分支作为工程基座

## 状态
已采纳

## 背景
仓库从零起步，需要可运行的前后端工程。要求：Java 21 / Spring Boot 4.x、前端 Vue3+TS、金仓成熟案例、自带代码生成器，且必须是单体形态。

## 选项

| 选型 | 优点 | 缺点 |
|------|------|------|
| 官方 RuoYi-Vue3 | 若依官方原版、社区资料多 | JDK 8 + JS 旧技术栈，不满足 Spring Boot 3 / TS |
| RuoYi-Vue-Plus 6.X 分支 | Spring Boot 4.x + Vue3+TS + 金仓案例 + 代码生成器全满足；dromara 社区活跃 | 迭代快、API 可能有变化，需锁定提交号冻结版本 |
| RuoYi-Cloud-Plus | 微服务能力全 | 形态过重，超出单体需求，运维复杂 |
| 自研脚手架 | 完全可控、无外部依赖 | 损失现成权限/日志/代码生成器，研发成本高 |

## 决策
选择 RuoYi-Vue-Plus `6.X` 分支作为工程基座。

## 理由
- 唯一同时满足"Spring Boot 4.x + Vue3+TS + 金仓成熟案例 + 代码生成器"四项的选项，无需自行拼装技术栈。
- 单体 `6.X` 分支结构最贴合本项目单体形态，裁剪成本低。
- dromara 社区活跃，国内金仓适配案例多，踩坑有前人兜底。
- 包名由默认 `org.dromara` 统一改为 `com.openspec.project`，与 AGENTS.md 约定一致。
- 主要代价是跟随社区迭代：通过锁定具体提交号、冻结依赖版本控制风险。
